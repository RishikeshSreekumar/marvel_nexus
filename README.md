# Marvel Nexus

An Astro + React recreation of the Marvel Nexus MCU chronology and story-dependency navigator. It contains 79 canonical season-level timeline stops and 18 legacy branch titles from the October 2026 data cut, plus a character tree covering every important character, heroes, supporting cast and villains, across 20 teams.

Pages: `/` (home), `/graph` (dependency map, with a Map/List toggle), `/timeline` (chronology) and `/characters` (team tree, mantle lineages, per-character appearances).

## Run locally

Requires Node.js 20.11 or newer.

```bash
npm install
npm run dev
```

Astro prints the local URL, normally `http://localhost:4321`.

Production verification:

```bash
npm run check
npm test
npm run build
npm run preview
```

## Project structure

- `src/pages/index.astro` owns the HTML shell, metadata, icons, and React island.
- `src/components/MarvelNexus.tsx` contains the story dataset and interactive navigator.
- `src/lib/graph.ts` contains the exported types, validation, graph traversal, sorting, URL state, and watched-state helpers.
- `src/styles/global.css` contains the design tokens and responsive visual system.
- `src/lib/characters.ts` holds the character bible's types, teams and helpers; the roster itself lives in `src/lib/cast/`, one file per team, plus `relations.ts`.
- `src/lib/portraits.json` maps character ids to portrait images, generated by `npm run portraits`.
- `src/components/CharacterTree.tsx` renders `/characters`; `PathList.tsx` is the graph's list layout; `PremiereCountdown.tsx` counts down to the next announced premiere.
- `tests/graph.test.ts` validates the dataset and derived behavior; `tests/characters.test.ts` validates the character data against the story ids.

## Editing stories

Use a stable, URL-safe `id` and add each title through the `s(...)` helper in `src/lib/stories.ts`. Canonical MCU entries belong in `chronologyInput`; alternate legacy universes belong in `legacyInput`.

The dependency list contains story IDs that must already exist somewhere in the combined dataset. Dependencies point from required context toward the title that requires it. The application validates duplicate IDs, missing references, self-links, cycles, and the expected 97/79/18 counts at startup and in tests.

Add a new released title to `releaseSequence` if it should participate in release-order sorting. Mark texture-only entries with `optional: true`, announced titles with `upcoming: true`, and uncertain placements with `editorialPlacement: true`.

Give an upcoming title a `premiere: "yyyy-mm-dd"` to put it in the countdown; once the date passes the countdown moves on to the next one, and disappears when none is left. The one-tap destinations above the map come from `featuredDestinations` in `src/lib/stories.ts`.

## Editing characters

Add a character to its team's file in `src/lib/cast/`, most important characters first. `appearances` are story ids and must exist in `stories.ts`. Set `doomsday: true` only for officially confirmed cast; the tests require the flag and a `"doomsday"` appearance to agree. Record a passed-on title with `mantles: [{ title, from }]`; chains are built from those links. Set `wiki` to the English Wikipedia article for the portrait (the character's screen article if one exists, otherwise the actor's), then run `npm run portraits` to refresh `portraits.json`. Characters without a portrait show their initials.

Watched progress is stored only in the browser under `marvel-nexus-watched`. The payload is versioned and unknown or malformed IDs are ignored.
